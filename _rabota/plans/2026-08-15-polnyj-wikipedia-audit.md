# Полный многоязычный Википедия-аудит: план выполнения

> **Для агентных исполнителей:** ОБЯЗАТЕЛЬНЫЙ ПОДНАВЫК: выполнять план последовательно через `superpowers:executing-plans`. Пункты отмечаются флажками `- [ ]`; параллельные исполнители для этой работы не используются.

**Цель:** создать воспроизводимый построчный аудит всего читательского текста зафиксированной версии `index.html`, сопоставить атомарные утверждения с шестью Википедиями и согласованными профильными источниками, а также отдельно перечислить относящиеся к Сербии объекты wein.plus и SerbianWine.rs, которых нет в книге.

**Архитектура:** зафиксированный HTML сначала преобразуется только для чтения в последовательный JSONL-манифест содержательных блоков. Из него вручную, с машинной проверкой схемы и полноты, строятся реестр атомарных утверждений, журнал источников, журнал решений и обратный каталог. Итоговый Markdown собирается из проверенных журналов, но формулировки сравнений и выводов остаются редакторскими, а не генерируются эвристикой.

**Технологии:** Python 3 и стандартная библиотека (`html.parser`, `json`, `pathlib`, `hashlib`, `urllib.parse`), JSONL, Markdown, Git, публичные страницы Википедий, VIVC, wein.plus и SerbianWine.rs.

## Общие ограничения

- Проверяется Git blob `60caf935aed22dca9054283876f9b8949158fa39` файла `index.html`.
- Рабочая ветка: `audit/polnyj-wikipedia-audit`.
- `index.html` и остальные файлы книги не изменяются.
- Итоговый файл: `_rabota/polnyj-wikipedia-audit-2026-08-15.md`.
- Порядок прямого аудита соответствует порядку книги.
- Каждое атомарное утверждение получает стабильный ID `C0001`, `C0002` и далее.
- Каждый кандидат обратного каталога получает стабильный ID `G0001`, `G0002` и далее.
- Для каждого утверждения проверяются английская, немецкая, венгерская, сербская, русская и хорватская Википедии; отсутствие материала записывается явно.
- VIVC имеет предметный приоритет для идентичности, синонимов и происхождения сортов.
- Открытые материалы wein.plus используются как источник; размытый или иной закрытый Premium-текст не извлекается и не восстанавливается.
- Дегустационная заметка является одной профессиональной оценкой, а не сенсорным консенсусом.
- Конкретному вину не приписывается общий сортовой профиль без явной маркировки.
- Определения и дескрипторы пересказываются самостоятельно; длинные цитаты и структура источников не копируются.
- Коммерческие, партнерские и предоставленные производителем материалы маркируются и не создают независимый консенсус.
- Если исчерпывающий обратный каталог технически невозможен, предел полноты описывается точно.

## Структура рабочих файлов

- `_rabota/audit/build_manifest.py`: только читает `index.html`, выделяет содержательные блоки и пишет JSONL.
- `_rabota/audit/tests/test_build_manifest.py`: проверяет порядок, извлечение интерактивного текста и исключение служебной навигации.
- `_rabota/audit/manifest.jsonl`: последовательный реестр всех проверяемых читательских блоков.
- `_rabota/audit/claims.jsonl`: атомарные утверждения книги.
- `_rabota/audit/coverage.jsonl`: явная классификация блоков, в которых нет проверяемых фактов.
- `_rabota/audit/sources.jsonl`: поязычные и профильные источниковые записи.
- `_rabota/audit/decisions.jsonl`: статус, консенсус, сравнение и редакторский вывод по каждому `C`-идентификатору.
- `_rabota/audit/gaps.jsonl`: обратный каталог wein.plus и SerbianWine.rs.
- `_rabota/audit/validate_audit.py`: проверка схем, ссылочной целостности, ID и покрытия.
- `_rabota/audit/tests/test_validate_audit.py`: тесты валидатора на корректных и ошибочных мини-наборах.
- `_rabota/audit/render_report.py`: детерминированная сборка итогового Markdown из журналов.
- `_rabota/audit/tests/test_render_report.py`: проверка обязательных разделов и отсутствия пустых полей.
- `_rabota/polnyj-wikipedia-audit-2026-08-15.md`: единый итоговый документ для редактора.
