# Начни отсюда

Это записка для сессии, которая продолжит работу **на машине автора**, где
сайты открываются. Всё, что можно было сделать без сети, сделано; всё, что
осталось, упирается ровно в неё.

---

## Задача

Рейтинги сербских вин — оценки покупателей и оценки критиков — собрать,
разложить по десяти главам книги и отобрать по каждой пятёрку с учётом
не только балла, но и числа отзывов. Под будущие подсказки к названиям вин
или отдельную рубрику в главах.

**Книгу не трогать.** `index.html` в этой работе не менялся ни на знак
и меняться не должен: рейтинги пока живут отдельно, решение о том, входят
ли они в книгу и в каком виде, за автором.

## Что уже есть

| | Сколько |
|---|---|
| Хозяйства | 72 |
| Вина | 403 |
| Оценки | 396 (317 Vivino, 79 стобалльных) |
| Награды | 55 (vino.rs, Decanter, AWC Vienna) |
| Пятёрки по районам | полные 2 из 10 |

Данные лежат тремя нормализованными таблицами (`hozyaistva`, `vina`,
`ocenki`) плюс `nagrady`, в JSONL и CSV. Поля описаны в `slovar-polej.md`.
Таблицы руками не правятся — они пересобираются из сырья.

## Чего не хватает и почему

Всё собрано через поиск, потому что из прежней среды сайты были закрыты
политикой исходящего трафика. Поиск отдаёт пересказ страницы, а не страницу.
Отсюда три дыры:

1. **У 202 оценок Vivino из 317 неизвестно число отзывов.** Счётчик на
   странице вина рисуется сценарием, и в кэш поиска попадает заглушка
   `count ratings`. Без числа отзывов вино в пятёрку не пускается — это
   прямое требование автора, и обходить его нельзя.
2. **Списки Falstaff прочитаны меньше чем наполовину**: 55 оценок из
   примерно 112.
3. **Поимённых серебра и бронзы Decanter нет ни за один год.** Только за
   2026-й это 136 медалей.

Причина у всех трёх одна: списки подгружаются отдельным запросом за JSON,
и в исходном HTML их нет.

## Что делать первым делом

Из корня репозитория, в PowerShell:

```
py -3 -m pip install playwright
py -3 -m playwright install chromium
```

### Шаг 1. Vivino целиком

```
py -3 _rabota\rejtingi\sobrat-rejtingi.py
```

Браузер не нужен: это обычные запросы к API сайта. Должен вернуть около
двух тысяч сербских вин с оценкой **и числом отзывов** — то есть закрыть
дыру номер один целиком. Складывает в `vivino-syrye.json`.

**Он на живом сайте не проверялся.** Если ответ разобрался не так,
править надо одну функцию — `razobrat_vino`; всё остальное от устройства
ответа не зависит. Признак беды: «в собранном нет ни одной оценки».

### Шаг 2. Остальные три источника

```
py -3 _rabota\rejtingi\sobrat-brauzerom.py --pokazat-otvety --vidimyj
```

Playwright открывает страницы и слушает, какой JSON они получают от своего
сервера. **Начинать надо именно с `--pokazat-otvety`**: он печатает адреса
всех перехваченных ответов, и по ним сразу видно, откуда страница берёт
список. По этим адресам и правятся `razobrat_falstaff` и `razobrat_decanter`.
`--vidimyj` показывает окно браузера — на первом запуске так понятнее.

Когда разбор сойдётся, запускать уже без ключей.

### Шаг 3. Пересобрать и проверить

```
py -3 _rabota\rejtingi\sobrat-tablicy.py
py -3 _rabota\rejtingi\proverit-dannye.py
```

`sobrat-tablicy.py` сам подхватит `vivino-syrye.json`, если он появился,
и при совпадении предпочтёт его ручным выпискам — там оценка и число
отзывов приходят полями, а не пересказом. Ручное не выбрасывается: в нём
могут быть вина, которых сплошной обход не вернул.

### Шаг 4. Пересчитать пятёрки и отчёты

```
py -3 _rabota\rejtingi\svesti-pyaterki.py --otchet
py -3 _rabota\rejtingi\svesti-kritikov.py --otchet
```

Ключ `--otchet` собирает готовый файл сам — вступление плюс таблицы.
Склейкой в оболочке этого делать не надо: в PowerShell перенаправление
пишет не в UTF-8, и отчёт выйдет в кракозябрах. Без ключа скрипты просто
печатают результат на экран.

После этого пятёрки должны собраться в большинстве районов, а не в двух.

## Что придётся решать не скрипту

**Районы.** У четырнадцати хозяйств район не установлен. Часть — за
пределами десяти глав книги (Milijan Jelić в Валеве, Vila Vina в Западной
Мораве). Про Virtus известно, что Decanter относит его к району **Млава**,
а не к Шумадии, как пишет Vivino; входит ли Млава в главу «Подунавье» —
вопрос к автору. Карта лежит в `raion-hozyaistv.json`, у каждой записи
проставлено, откуда взят район.

**Годовой тест vino.rs.** Скрипт откроет страницы и напечатает строки
итогов, но раскладывать их по тридцати категориям надо глазами: категории
подписаны прозой, и машина здесь ошибётся тихо. Разобранное переносится
в `dobavit-nagrady.py`.

**Wine-Searcher** закрывается от автоматического чтения. Ломать защиту
не нужно: сербских вин там немного, дешевле дособрать руками.
**wein.plus** — оценки за регистрацией.

## Чего делать нельзя

- **Править `index.html` скриптом.** Прямое требование автора: массовые
  замены дважды ломали текст. Правки в книгу вносятся руками, точечно,
  с перечитыванием окружающих абзацев. Подробности в корневом `CLAUDE.md`.
- **Смешивать шкалы.** 4,2 у Vivino и 92 у Falstaff — разные величины,
  а не одна в разных единицах. В `ocenki` у каждой строки написано, чья
  шкала; складывать их нельзя.
- **Ранжировать оценку без числа отзывов.** Ради этого всё и затевалось.
- **Переводить награды в баллы.** У «лучшего белого из местных сортов
  2025 года» нет шкалы; для наград отдельная таблица.

## Что стоит закоммитить после сбора

`vivino-syrye.json` и обновлённые `kritiki-zapisi.jsonl`,
`nagrady-zapisi.jsonl` — это собранные данные, они ценные. Каталог
`_rabota` на сайт не публикуется, размер там не важен.
